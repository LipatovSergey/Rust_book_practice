# Option и null в Rust

В Rust вообще нет `null`. `null` в других языках программирования например в `JS` приводит к проблеме с которой даже я сталкивался не раз. Например функция принимает какой-то аргумент значение которого может быть `null`. При этом в самой функции не обрабатывается такой вариант. Это приводит к ошибке, при чём можно вообще очень долго с ней не сталкиваться при разработке.

В Rust для работы со значениями которых нет вообще или они не получены по какой-то причине используется встроенный `enum`(перечисление) `Option`.

```rust
enum Option<T> {
  None,
  Some(T)
}
```

`<T>` ещё будет более подробно разбираться в 10ой главе. Пока, что достаточно знать что вариант `Some` может содержать один фрагмент любого типа. Примеры использования:

```rust
  let some_number = Some(5);
  let some_char = Some('e');

  let absent_number: Option<i32> = None;
```

Для переменной absent_number нужно в ручную указывать тип, потому что Option ожидает `<T>`. В some_number и some_char Rust выводит тип автоматически на основе данных которые передаются в Some.

Так чем же это лучше чем null? Всё очень просто. Компилятор Rust выбросит ошибку если попытаться скомпилировать такой код:

```rust
    let x: i8 = 5;
    let y: Option<i8> = Some(5);

    let sum = x + y
```

То есть Rust говорит. Переменная `y` может не иметь значение (является вариантом None). С ним нельзя производить никаких действий пока не будет уверенности, что значение действительно есть. Rust заставляет обрабатывать вариант с отсутствующим значением. Не позволяя разработчику допустить ошибку.
