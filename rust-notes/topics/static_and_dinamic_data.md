# Статические и динамические данные в Rust

## Две фундаментальные категории данных

На высоком уровне все данные в программе можно разделить на две принципиально разные группы:

---

### 1️⃣ Статические данные

**Статические данные** существуют **с момента загрузки программы в память** и живут **весь runtime процесса**.

Характерные свойства:

- определяются на этапе компиляции
- загружаются в память вместе с бинарником
- **размещаются в специальных статических сегментах памяти процесса**
  (обычно `.rodata`, `.data`, `.bss`)
- **не находятся ни в стеке, ни в куче**
- не создаются и не уничтожаются во время выполнения
- не управляются через `drop`
- не имеют владельца в пользовательском коде
- доступны на протяжении всей работы программы

Примеры:

- строковые литералы (`"hello"`)
- `const`
- `static`

Строковые литералы имеют тип `&'static str`.
Это означает, что ссылка на такие данные **гарантированно валидна весь runtime программы**,
а не то, что переменная, содержащая эту ссылку, живёт вечно.

Важно понимать:

- переменные, указывающие на статические данные, подчиняются обычным правилам областей видимости
- сами данные при этом **не исчезают**, когда переменная выходит из scope
- уничтожается только ссылка (переменная), а не данные

---

### 2️⃣ Динамические данные

**Динамические данные** создаются **во время выполнения программы** и имеют ограниченное время жизни.

Характерные свойства:

- появляются после старта программы
- размещаются в:
  - **стеке**
  - **куче**
  - или используют их комбинацию

- всегда имеют владельца
- подчиняются правилам владения и заимствования
- автоматически очищаются при уничтожении владельца

Примеры:

- `String`
- `Vec<T>`
- `Box<T>`
- любые данные, выделяемые динамически

Для многих типов данные распределены между стеком и кучей.
Например, `String`:

- в стеке хранит метаданные (указатель, длина, capacity)
- в куче хранит сами байты строки

Очистка динамических данных происходит детерминированно:

- владелец выходит из области видимости
- вызывается `drop`
- ресурсы освобождаются

---

## Размещение в памяти процесса

После запуска программы **и статические, и динамические данные находятся в памяти процесса**,
однако **они размещаются в принципиально разных областях памяти**.

- **Статические данные**
  - находятся в отдельных статических сегментах памяти
  - не используют стек и кучу
  - существуют весь runtime программы
  - не участвуют в механизмах динамического выделения и освобождения памяти

- **Динамические данные**
  - используют стек, кучу или их комбинацию
  - создаются и уничтожаются во время выполнения
  - управляются через модель владения Rust

> Стек и куча предназначены исключительно для динамических данных.
> Статические данные живут отдельно и не смешиваются с ними.

---

## Связь с моделью владения Rust

Модель владения Rust в первую очередь предназначена для **динамических данных**.
Именно для них строго отслеживается:

- единственный владелец
- время жизни
- отсутствие висячих ссылок

Статические данные живут **вне этой модели**:

- у них нет владельца в пользовательском коде
- их жизненный цикл совпадает с жизнью программы
- Rust лишь гарантирует безопасный доступ к ним через ссылки
